# 안드로이드 수신 앱 2차 — 소파에서 보정하기 + 드리프트 진단

1차 앱([PROMPT.md](PROMPT.md))이 동작한 뒤에 붙이는 기능이다.
PC 쪽은 이미 구현·검증돼 있고, 아래 `trim` 메시지를 받으면 즉시 반영한다.

## 왜 필요한가

립싱크를 맞추려면 지금은 PC 앞으로 가서 스핀박스를 조작해야 한다.
시청 위치는 방 하나 건너에 있으므로 실용적이지 않다.

그리고 PC 와 폰의 48000 Hz 는 정확히 같지 않다. 어긋난 만큼 폰의 지터 버퍼가
서서히 차거나 마르는데, **50 ppm 만 어긋나도 2시간 영화면 360 ms 가 밀린다.**
지금은 이 값이 PC 의 CSV 에만 쌓여서 영화가 끝난 뒤에야 확인할 수 있다.
폰 화면에서 실시간으로 보이면 바로 알 수 있다.

## 프롬프트 (여기부터 복사)

기존 오디오 수신 앱에 두 가지를 추가해줘.

### 1. 지연 보정 조절 (소파에서 립싱크 맞추기)

영상은 PC 에서 나오고 소리만 폰으로 오기 때문에, 어긋나면 PC 가 영상을 늦춰서 맞춘다.
그 보정값을 **폰에서 조절**할 수 있게 해줘. PC 앞까지 갈 필요가 없도록.

- 화면에 보정값 조절 UI (슬라이더 + `−10ms` / `+10ms` 버튼). 범위 −200 ~ +300 ms
- 값이 바뀌면 컨트롤 채널로 **즉시** 보낸다:

```json
{"type":"trim","offset_ms":40}
```

- 접속 시 PC 가 보내는 `hello` 에 `trim_ms` 필드가 들어 있다. 현재 PC 에 설정된 값이므로
  UI 초기값으로 쓸 것:

```json
{"type":"hello","protocol":1,"trim_ms":0,"audio":{...}}
```

- **＋ 방향이 "소리가 늦게 들릴 때"** 다. UI 에 그렇게 적어줘.
  (＋ 를 누르면 PC 가 영상을 더 늦춰서 소리에 맞춘다)
- 슬라이더를 끄는 동안 매 픽셀마다 보내지 말고, 10 ms 단위로 값이 바뀔 때만 보낼 것

### 2. 실시간 그래프 (드리프트 진단)

지금 측정 중인 값들을 시간축 그래프로 보여줘. 라이브러리 없이 `Canvas` 로 직접 그리면 된다.

- **가로축**: 최근 5분 (스크롤되는 창)
- **세로축**: 밀리초
- 그릴 값 세 가지:
  - **지터 버퍼 깊이** (가장 중요 — 이게 한쪽으로 계속 기울면 클럭 드리프트다)
  - **오디오 출력 지연** (`getTimestamp()` 측정값)
  - **총 지연** (위 둘 + 네트워크 편도)
- 언더런이 발생한 시점에 세로선 표시
- 그래프 아래에 숫자 요약: 현재 버퍼 / 출력 지연 / 언더런 누적 횟수

**드리프트 판정도 앱에서 해줘.** 버퍼 깊이의 최소제곱 기울기를 구해서 ppm 으로 환산한다:

```
ppm = (버퍼 기울기 ms/시간) / 3.6
```

- 5분 이상 데이터가 쌓였을 때만 표시
- `|ppm| < 5` → "안정" 초록
- `|ppm| >= 5` → "드리프트 ○○ ppm — 2시간에 약 ○○○ms 밀림" 주황
- 이 판정 로직은 PC 쪽 `tools/latency_report.py` 와 같은 기준이다

### 만들지 말 것

- 그래프를 위한 외부 차트 라이브러리 (Canvas 로 충분하다. APK 만 커진다)
- 폰에서 오디오를 늦추거나 당겨서 맞추려는 시도. **영상을 늦추는 건 PC 가 한다.**
  폰은 정확히 보고하고, 사용자가 조절한 값을 전달하기만 한다

## 이후 과제 (드리프트가 실제로 확인되면)

그래프에서 버퍼가 한쪽으로 계속 기우는 게 확인되면, 그때 **적응형 리샘플링**을 넣는다.
버퍼 수위를 보고 재생 레이트를 48000 ± 0.005% 수준으로 미세 조정해서 수위를 유지하는 방식이다.
Snapcast 나 AirPlay 가 쓰는 방법이고, 버퍼가 한계에 닿아 리셋되며 소리가 튀는 것을 막아준다.

**확인되기 전에는 만들지 말 것.** 구현이 까다롭고, 드리프트가 없으면 음질만 손해다.
