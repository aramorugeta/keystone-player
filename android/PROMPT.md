# 안드로이드 수신 앱 — 개발 프롬프트

Android Studio 의 AI 어시스턴트에 아래 내용을 그대로 붙여넣으면 된다.
PC 쪽(이 저장소의 `net_audio.py`, `audio_dsp.py`)은 이미 구현·검증돼 있고,
아래 프로토콜은 **실제로 동작하는 구현에서 뽑은 값**이다. 임의로 바꾸면 안 된다.

---

## 프롬프트 (여기부터 복사)

리눅스 PC 의 영상 플레이어가 보내는 오디오를 받아서 재생하는 안드로이드 앱을 만들어줘.
심야에 프로젝터로 영화를 보면서 소리는 폰에 꽂은 이어폰으로 듣기 위한 것이다.

**가장 중요한 요구사항**: 이 앱은 자기 재생 지연을 정확히 측정해서 PC 로 보고해야 한다.
PC 가 그 값만큼 영상을 늦춰서 립싱크를 맞추기 때문이다. 지연 보고가 부정확하면
입모양이 어긋나서 앱 전체가 쓸모없어진다. 지연 측정을 최우선으로 정확하게 구현해줘.

### 오디오 수신

- 전송: **RTP over UDP**, 앱이 **UDP 46000** 포트를 열고 수신 대기 (PC 가 이쪽으로 쏜다)
- 패킷: 972 바이트 고정 (RTP 헤더 12 바이트 + 페이로드 960 바이트)
- RTP 헤더: 버전 2, payload type 127. **헤더 12바이트를 버리고 나머지를 그대로 쓰면 된다.**
  확장 헤더나 CSRC 는 오지 않는다. 시퀀스 번호는 헤더 2~3 바이트 빅엔디언 uint16.
- 페이로드 포맷: **PCM 16비트 빅엔디언(S16BE), 48000 Hz, 스테레오 인터리브**
  - 960 바이트 = 240 프레임 = 정확히 5 ms
  - **안드로이드 `AudioTrack` 은 리틀엔디언을 기대하므로 바이트 스왑이 필요하다.**
    (`ByteBuffer.order(ByteOrder.BIG_ENDIAN).asShortBuffer()` 로 읽어서 short 배열로 넘기면 된다)
- 무압축이므로 대역폭은 1.5 Mbps. 디코딩 불필요.

### 오디오 출력

- **Oboe 또는 AAudio** 를 저지연 모드로 쓸 것 (`PerformanceMode.LowLatency`, 배타 공유 모드 우선)
- 샘플레이트 48000, 스테레오. 기기 네이티브 레이트가 48000 이 아니면 리샘플링 대신
  `AudioTrack` 에 맡기되, 그 경우 지연이 커지므로 보고값에 반영해야 한다.
- 적응형 지터 버퍼:
  - 시작 버퍼 60 ms, 하한 20 ms, 상한 200 ms
  - 언더런이 발생하면 20 ms 씩 늘리고, 30 초간 언더런이 없으면 10 ms 씩 줄인다
  - **현재 버퍼 크기를 항상 알고 있어야 한다** (PC 에 보고해야 하므로)
- 시퀀스 번호로 패킷 유실·순서바뀜을 처리한다. 유실 시 무음(0) 을 채워 넣고,
  **재생 위치를 절대 앞당기지 말 것** (지연이 흔들리면 립싱크가 깨진다)

### 지연 측정 (가장 중요)

PC 에 보고할 값은 두 개다.

1. `output_ms` — 오디오 하드웨어 출력 지연.
   `AudioTrack.getTimestamp(AudioTimestamp)` 로 얻은 프레임 위치와 나노초 타임스탬프로 계산하거나,
   Oboe 의 `AudioStream::getTimestamp()` 를 쓴다.
   **추정값을 하드코딩하지 말고 실제로 측정해서 넣을 것.**
2. `buffer_ms` — 현재 지터 버퍼에 쌓여 있는 오디오의 길이.

두 값을 **1 초마다** PC 로 보고한다. 값이 튀지 않도록 최근 몇 개의 중앙값을 쓰는 것이 좋다.

### 컨트롤 채널 (TCP)

- 앱이 **PC 의 TCP 46001** 로 접속한다. PC 주소는 사용자가 앱 화면에서 직접 입력한다
  (PC 앱 화면에 표시되는 주소를 보고 입력. 자동 탐색은 나중 과제)
- 메시지는 **UTF-8 JSON 한 줄에 하나씩, `\n` 으로 끝난다**

PC → 앱:

```json
{"type":"hello","protocol":1,"audio":{"transport":"rtp","port":46000,"format":"s16be","rate":48000,"channels":2,"packet_ms":5}}
{"type":"ping","t":1234567}
{"type":"stop"}
```

- `hello` — 접속 직후 한 번. 이 값으로 오디오 설정을 맞춘다.
  `protocol` 이 1 이 아니면 사용자에게 버전 불일치를 알린다.
- `ping` — 2 초마다. `t` 는 PC 의 단조 시계 밀리초. **받는 즉시 그대로 되돌려줘야 한다.**
  이 왕복 시간으로 PC 가 네트워크 편도 지연을 계산한다. 응답을 지연시키면 립싱크가 틀어진다.
- `stop` — PC 가 네트워크 출력을 껐다는 뜻. 재생을 멈추고 연결을 정리한다.

앱 → PC:

```json
{"type":"ready","device":"Galaxy Z Fold7","app":"1.0"}
{"type":"pong","t":1234567}
{"type":"latency","output_ms":42,"buffer_ms":80}
{"type":"trim","offset_ms":40}
{"type":"bye"}
```

- `ready` — 접속 직후 한 번. `device` 는 PC 화면에 표시된다.
- `pong` — `ping` 의 `t` 를 **그대로** 돌려준다. 값을 바꾸면 안 된다.
- `latency` — 1 초마다. 위에서 측정한 두 값.
- `trim` — 사용자가 폰에서 립싱크를 직접 조절했을 때. 2 차 기능이므로
  [PROMPT2.md](PROMPT2.md) 참고. 1 차에서는 보내지 않아도 된다.
- `bye` — 사용자가 앱을 끌 때.

TCP 연결이 끊기면 PC 는 자동으로 로컬 스피커 출력으로 되돌아간다.

### 안정성 (실사용에서 제일 문제되는 부분)

- **포그라운드 서비스**로 구현할 것. 화면이 꺼져도 재생이 유지돼야 한다
- `WifiManager.WifiLock` (`WIFI_MODE_FULL_LOW_LATENCY`) 을 잡을 것.
  이걸 안 하면 화면이 꺼진 뒤 WiFi 전원절약이 걸려서 끊기고 지터가 폭증한다
- 부분 wakelock 도 함께 잡는다
- 배터리 최적화 예외를 요청하는 안내를 넣어줄 것 (Doze 로 죽는 것 방지)
- 필요 권한: `INTERNET`, `ACCESS_NETWORK_STATE`, `ACCESS_WIFI_STATE`,
  `WAKE_LOCK`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, `POST_NOTIFICATIONS`

### UI (최소한으로)

- PC 주소 입력란 + 접속/해제 버튼 (마지막 주소 기억)
- 현재 상태: 연결됨/끊김, 측정된 출력 지연, 현재 버퍼 크기, 언더런 횟수
- 볼륨은 폰 하드웨어 볼륨키로 조절 (앱 자체 볼륨 슬라이더 불필요)

### 만들지 말 것

- 오디오 코덱/압축 (무압축이 목적이다. 지연과 음질 둘 다 손해)
- 자체 지연 보정 (영상을 늦추는 건 PC 가 한다. 앱은 정확히 보고만 하면 된다)
- 재생 속도 조절로 버퍼를 맞추는 로직 (음정이 흔들린다)

## 개발 중 참고

### PC 쪽 켜는 법

1. `python3 main.py` 실행
2. 「사운드 보정」의 **볼륨 평준화** 체크 (RTP 송출이 DSP 체인 안에 있어서 필요)
3. 「폰으로 소리 보내기」의 **네트워크 출력** 체크
4. 화면에 표시된 `주소 : 46001` 을 앱에 입력

### 앱 없이 프로토콜만 시험하기

`scratchpad/nettest.py` 와 같은 방식으로 가짜 폰을 만들어 붙여볼 수 있다.
PC 쪽 검증 시 실제로 확인된 값:

```
RTP 패킷 972 바이트 고정 | 페이로드 960 바이트 | RTP v2 payload-type=127
hello / ping / pong / latency 왕복 정상
보고 지연 40+80ms + 편도 → 영상 지연 자동 설정 확인
```

### 지연 예산 감각

| 구간 | 예상 |
|---|---|
| PC 송출 버퍼 | 20 ms (고정) |
| WiFi 편도 | 5~30 ms (혼잡도에 따라) |
| 폰 지터 버퍼 | 40~120 ms |
| 폰 오디오 출력 | 20~50 ms (기기별) |
| **합계** | **85~220 ms** |

영상 지연 보정은 최대 800 ms 까지 지원한다. 폰에 블루투스 이어폰을 물리면
A2DP 지연 150~250 ms 가 더해지므로 그만큼 여유가 필요하다.
합계가 계속 300 ms 를 넘으면 WiFi 5 GHz 를 쓰거나 USB 테더링을 검토할 것.
